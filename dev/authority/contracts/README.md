# Authority Contracts

Purpose: repository-level documentary contracts whose governing force extends across planning or implementation.

Allowed artifact classes: frozen cross-component contracts, architecture contracts, interface/ownership contracts, and durable repository-wide engineering constraints.

Prohibited artifact classes: temporary implementation plans, task prompts, run evidence, review reports, or current-state journals.

Authority status: a contract is authoritative only when established by the project authority system. Placement here does not independently create authority.

Naming: use concise lowercase kebab-case filenames unless an existing authoritative contract name must be preserved.
