## Frozen source observations

1. **Thin canonical reuse — conformant on source.** `run-deterministic-scenario.ts` resolves only an exact ID through its static catalog and calls the existing `DeterministicScenarioRunner.canonical().run(selected)` once. The existing runner retains status/classification/evidence authority. Its module is entirely under `test-platform/test/batteries/`; no live transport is invoked. `deterministic-scenario-registry.ts` validates mapped definitions, duplicate IDs/source entries, and deterministic-only modes, with stable sorted discovery.
2. **Strict argument validation and read-only discovery — conformant on source.** Parser requires sole `--list-scenarios` or exactly two distinct `--scenario` and `--result-file` pairs; rejects bad IDs, traversal components, UNC/network path prefixes, nonabsolute/non-json/oversized paths, and unknown flags. Discovery produces schemaVersion-1 JSON listing without running a scenario.
3. **Pre-dispatch collision protection — conformant on source.** After parsing but *before* catalog selection or runner invocation, output destination is atomically reserved via `open(request.resultFile,"wx")`, preventing an existing output from being overwritten and resolving concurrent same-file attempts without allowing the loser to dispatch. A failed reservation returns classification `scenario-result-persistence-failed`, phase `result-reservation`, no confirmed effect, nonzero exit.
4. **Selection rejection receives durable, noncanonical record — conformant on source.** If selected ID is absent or not exclusively deterministic, the reserved result is populated with `schemaVersion:1`, requested ID, deterministic mode, `requestStatus:"rejected"`, `result:null`, and typed safe diagnostic; stdout does not claim a completed scenario and exit is nonzero. This record is *not* fabricated canonical scenario evidence. Malformed argv without validated result path remains stderr-only, appropriately.
5. **Canonical post-dispatch evidence/exit — conformant on source.** The CLI checks result ID, machine evidence ID/mode/status, and writes only canonical privacy-screened machine evidence to its exclusive file. It prints short status/classification summary and maps all noncompleted statuses to nonzero. Raw runner captures are excluded; unknown exceptions are not printed.
6. **Fault/persistence handling — bounded concerns for Pass 2.** Runner throws or identity validation faults produce a diagnostic classified `scenario-cli-execution-failed` with UNKNOWN effect and a `requestStatus:"rejected"` envelope, despite potential initiation of in-memory scenario work. That `rejected` value could be misread as pre-dispatch rejection without consulting phase/effect; the diagnostic itself is truthful. Also, output summary is printed and exit set before file-handle close; a rare close failure changes exit to 1 after printing `"completed"`. The result file can be incomplete after a write failure or interruption, correctly non-PASS per contract; acceptance needs evidence proving fail-closed operator verification, rather than assuming every file exists/was completely written.
7. **Source completeness and deliberate fault injection — proof obligations.** Static catalog alone cannot detect a new unlisted source module. Independent Pass 2 must verify source-inventory oracles covering every supported deterministic scenario, and realistic CLI post-dispatch blocked/failed/unsupported outcomes through the compiled Node boundary without public arbitrary module selection, malicious imports or a second runner.
